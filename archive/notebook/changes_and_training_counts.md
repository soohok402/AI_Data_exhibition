# 고정 5-Fold 잔차 분류 실험 — 변경 내역과 실행 안내

## 1. 어느 셀부터 실행하는가

기존 공통 1~6을 이미 실행했다면 새 Notebook의 **`공통 4 — 재실행 시작`** 코드 셀부터 실행한다. 데이터 로딩 셀을 다시 실행할 필요는 없다. 이후 원하는 PART만 실행한다.

- 새 커널에서는 공통 1부터 순서대로 실행한다.
- 현재 Notebook에서 작업을 이어가려면 기존 공통 함수 정의 구간 이후를 새 Notebook의 공통 4 이후로 교체한다. 과거 PART A/B 셀과 섞어 실행하지 않는다.
- A 최초 실행: 공통 4 → A1 → A2 → A3 → A4 → A5 → A6.
- A 임계값만 변경: **A4 → A5 → A6**. A1~A3을 재실행하지 않으면 저장된 잔차와 기준 예측을 재사용한다.
- B 최초 실행: 공통 4 → B0(확정 임계값 입력) → B1 → B2 → B3 → B5.
- B 임계값만 변경하는 경우: B0 → B5. 다만 본실험 임계값 결정은 사용자가 수행한다.
- B0는 `final_threshold=None`이면 학습 준비 전에 중단한다. A의 값을 자동으로 가져오지 않는다.
- 데이터·변수·Fold·회귀 설정·조기 종료 설정을 바꾸면 공통 준비 및 해당 PART의 잔차·기준모델 준비부터 재실행한다. 서명/설정 검증은 오래된 잔차의 잘못된 재사용을 차단한다.

이번에 **실제 모델 학습은 한 번도 실행하지 않았다.** 축소 모델 학습도 실행하지 않았다. 사용자가 직접 학습하고 결과를 분석하는 코드 산출물이다.

## 2. 바꾼 셀과 이유

| 셀 | 변경 | 이유 |
|---|---|---|
| 첫 안내 Markdown | 고정 Fold·모델 종류·학습 횟수·재실행 순서 | 최종 파이프라인을 먼저 확인 |
| 공통 1 | 새 분할 관련 import 제거 | GroupShuffleSplit/새 GroupKFold 사용 금지 |
| 공통 2~3 및 설정·컬럼군 | 기존 데이터 로딩·32개 입력·row_id/Fold 검증 유지 | 기존 프로젝트와 연결 |
| 기존 공통 4~6 | 함수 정의 제거, 새 공통 4에 import·모델 설정·서명 준비 | 학습이 함수 호출 뒤에 숨지 않도록 함 |
| A1 | LightGBM 내부 회귀 20회 직접 나열 | 기존 고정 5-Fold 각각에 대해 제외 Fold/내부 Fold를 명시 |
| A2 | LightGBM Train 전체 회귀 OOF 5회 | Validation용 분류 정답 준비, 횟수 별도 공개 |
| A3 | LightGBM 기준 회귀 1회 | 임계값 간 같은 기준 예측 재사용 |
| A4 | `thresholds = [0.5, 1.0]` | 사용자 초기 후보 반영, 자동 선택 없음 |
| A5 | 임계값별 분류 5+1회, 실험 회귀 1회, 평가·저장 | 모든 모델을 LightGBM으로 통일 |
| A6 | Validation RMSE 비교 그래프 | 사용자 직접 비교 |
| B0 | `final_threshold=None` 직접 입력 | 미확정 상태에서는 학습 전에 중단 |
| B1~B3 | CatBoost 잔차 20+5회 및 기준 회귀 1회 | A와 별개로 재생성 |
| B5 | CatBoost 분류 5+1회, 실험 회귀 1회, 평가·저장 | 독립 Validation 최종 비교 |
| 마지막 Markdown | 핵심/추가/전체 학습 횟수 | 26회만으로 전체 평가가 끝난다고 오해하지 않도록 함 |

완성 Notebook에는 **`def`, 사용자 클래스, lambda가 없다.** A와 B에 필요한 코드를 각각 셀에 직접 작성했다. CatBoost 회귀는 `iterations=3000`, `random_state=42`, 기존 나머지 기본 설정을 유지한다. 내부 회귀에만 `early_stopping_rounds=100`을 적용한다. 기준·실험 본 회귀는 3000회 고정이며 eval_set을 사용하지 않는다.

A의 LightGBM 회귀는 신규 설정으로 `n_estimators=3000`, `learning_rate=0.05`, `num_leaves=31`, `random_state=42`를 명시했다. 내부 잔차 회귀는 내부 eval_set과 100회 early_stopping callback, 기준·실험 회귀는 같은 설정으로 eval_set 없이 학습한다. LightGBM 분류 설정과 CatBoost 분류 설정은 기존 코드의 값을 유지했다.

## 3. 분류 OOF와 Validation 범주 생성

예측 대상 Fold A를 제외한 B·C·D·E에서 회귀 OOF 4회를 수행한다. 각 내부 검증 Fold도 회귀 학습에서 제외한다. 네 Fold의 잔차를 합쳐 분류기를 1회 학습하고, A의 분류범주를 예측한다. 5개 예측 Fold에서 이를 반복하면 회귀 20회+분류 5회다.

회귀 잔차는 임계값과 무관하므로 A1/B1에서 Fold별 Series로 메모리에 보관한다. A5/B5에서 임계값으로 라벨링하고 분류기를 학습한다. 이 구현상 분리에도 불구하고 각 분류기의 정답은 **그 예측 Fold를 제외한 회귀 4회 결과**에 정확히 대응한다.

Validation의 범주는 별도의 분류기로 생성한다. 이 분류기는 A2/B2의 Train 전체 고정 5-Fold 회귀 OOF 잔차를 정답으로 사용한다. Validation 실제 종속변수는 분류 정답 생성이나 fit·eval_set에 전달하지 않는다.

본 회귀는 기존 31개 수치형 변수+station_id에 예측한 문자열 범주 `pred_residual_class` 하나만 추가한다. `residual_label`은 분류 학습 정답으로만 사용한다. LightGBM에서는 비순서형 pandas category 및 categorical_feature로, CatBoost에서는 문자열 cat_features로 처리한다. 숫자 0·1·2를 연속형 크기처럼 입력하지 않는다. `normal`의 표시 의미는 일반오차이고 경계는 `-t <= residual <= t`다.

## 4. 학습 횟수

### PART A: m개 후보

| 단계 | 회귀 | 분류 | 구분 |
|---|---:|---:|---|
| Train 중첩 잔차 준비 | 20 | 0 | 핵심·공통 |
| Train 분류 OOF | 0 | 5m | 핵심·임계값별 |
| 신규 변수 적용 회귀 | m | 0 | 핵심·임계값별 |
| Validation 분류기 정답 잔차 | 5 | 0 | 추가·공통 |
| Validation 범주용 분류기 | 0 | m | 추가·임계값별 |
| 신규 변수 없는 기준모델 | 1 | 0 | 추가·공통 |
| **합계** | **26+m** | **6m** | **26+7m** |

- 임계값 1개: 핵심 26회 + 추가 7회 = **33회**.
- 초기 임계값 2개: 핵심 32회 + 추가 8회 = **40회**(회귀 28, 분류 12).
- 준비 완료 후 임계값만 새로 m개 실행: **추가 7m회**. 잔차 생성과 기준 회귀 재학습 없음.

### PART B: 확정값 1개

| 단계 | 회귀 | 분류 |
|---|---:|---:|
| Train 중첩 분류 OOF | 20 | 5 |
| 신규 변수 적용 회귀 | 1 | 0 |
| **핵심 소계** | **21** | **5** |
| Validation용 분류 정답 잔차 | 5 | 0 |
| Validation용 분류기 | 0 | 1 |
| 기준모델 | 1 | 0 |
| **전체** | **27** | **6** |

B 전체는 **33회**다. A 초기 2개 + B 1개를 모두 실행하면 **총 73회**다. 단일 범주만 존재하는 분류 단계는 fit 대신 상수 예측으로 처리하며 경고와 `fit_performed=False`를 기록한다. 실제 분류 fit 횟수는 이 경우 줄어든다.

외부 Fold별 최종 회귀 성능 진단 90회는 없고, 회귀 OOF RMSE 진단도 추가하지 않았다. 기존 제공 OOF의 RMSE를 공통 셀에서 확인하는 계산만 기존대로 유지했다.

## 5. 결과와 저장

A5를 다시 실행하면 새 폴더를 만들어 지난 결과를 보존한다. B5도 동일하다. 한 후보별 폴더에는 다음을 저장한다.

- Fold별 분류 학습 정답 개수·비율.
- Train 전체 회귀 OOF 정답 개수·비율.
- Train 분류 OOF 및 Validation 예측범주.
- Train/Validation 예측범주 분포 및 Validation 평가 정답 분포.
- Validation 기준/실험 회귀 예측값, 평가용 정답, 혼동행렬.

실행 폴더에는 임계값별 `validation_results.csv`, 모델 설정, 회귀 학습 로그, 분류 fit 여부 기록을 저장한다. A에는 RMSE 비교 그래프도 저장한다. 임계값 결과는 입력 순서대로 표시하고 자동 argmin·선정·B 전달은 하지 않는다.

Macro F1은 Validation에서 평가한다. 정답은 `Validation 관측값 − 해당 PART의 기준 회귀 예측값`에 임계값을 적용한 값이다. 분류기의 predict 결과와 비교하며, 고정 3범주 평균을 사용한다. 없는 범주의 F1은 0이다. 이 평가 정답은 어떠한 회귀 입력에도 추가하지 않는다.

- `delta_rmse = 실험 − 기준`: 음수이면 개선.
- `improvement_rmse = 기준 − 실험`: 양수이면 개선.
- 개선율: `(기준 − 실험) / 기준 × 100`.

이번 요청대로 Validation 점수로 A의 임계값을 탐색하므로 Validation은 모델 선택에도 사용된다. B 점수를 완전히 새로운 미사용 평가 데이터의 성능으로 해석하지 않는다. 이는 Validation 타깃을 fit/조기 종료에 사용하는 것과는 별개다.

## 6. 학습 없는 검증

수행한 검사:

- 전체 코드 셀 Python 문법 컴파일 및 Notebook 스키마 검사.
- A만/B만 연결한 코드의 이름 참조 정적 검사: 미정의 이름 없음.
- 함수 정의 0개, 새 분할 호출 없음, 삭제된 경로 변수 참조 없음.
- A 학습 코드에 CatBoost 없음, B 학습 코드에 LightGBM 없음.
- eval_set 사용 위치가 내부 잔차 생성 셀뿐인지 AST 검사.
- 실제 Parquet를 읽어 행 수(616,293 / 133,316), row_id, 원래 OOF와 인덱스 순서, CSV Fold 일치를 확인.
- 실제 행 인덱스만으로 5×4 분할을 순회해 외부 Fold 및 Validation 제외, 내부 fit/eval 분리, 사상 분리, 행별 예측 대상 횟수 1회를 확인. 모델 생성·학습은 하지 않음.

**검증 중 모델 fit 실행 횟수는 0회다.** 실행 성능·분류 성능·RMSE 개선 여부는 미확정이다. 라이브러리 API 참고: [LightGBMRegressor 공식 문서](https://lightgbm.readthedocs.io/en/latest/pythonapi/lightgbm.LGBMRegressor.html).
